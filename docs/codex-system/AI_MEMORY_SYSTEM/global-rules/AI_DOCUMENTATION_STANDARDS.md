# AI Documentation Standards

## Documentation Philosophy

Documentation should be:

- compact
- useful
- maintainable
- high-signal
- easy to scan

Avoid:
- giant explanations
- redundant information
- documenting trivial changes

---

# Good Documentation

Good documentation contains:

- important decisions
- architecture notes
- reusable discoveries
- unresolved issues
- future warnings
- workflow explanations

---

# Bad Documentation

Avoid documenting:

- tiny UI tweaks
- obvious code behavior
- repetitive implementation details
- temporary experiments

---

# File Responsibilities

## PROJECT_STATE.md

Contains:
- current project status
- working systems
- pending work
- current priorities

Keep compact.

---

## AI_NOTES.md

Contains:
- important AI-specific instructions
- architecture warnings
- workflow rules
- reusable discoveries

---

## ARCHITECTURE.md

Contains:
- system structure
- component responsibilities
- major workflows
- critical dependencies

---

## KNOWN_ISSUES.md

Contains:
- unresolved bugs
- edge cases
- technical limitations
- dangerous areas

---

## CHANGELOG.md

Contains:
- major feature additions
- major fixes
- architecture changes

Do NOT log trivial changes.

---

# Writing Style

Prefer:
- bullet points
- short sections
- direct explanations
- compact formatting

Optimize for:
- fast AI reading
- low token usage
- quick retrieval
