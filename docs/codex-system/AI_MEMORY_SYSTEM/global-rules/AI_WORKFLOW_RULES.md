# AI Workflow Rules

## Core Philosophy

AI agents must prioritize:

- Clean architecture
- Modular code
- Minimal context waste
- Long-term maintainability
- Stable project evolution
- Consistent documentation

Avoid:

- giant context dumps
- unnecessary rewrites
- duplicated logic
- architecture drift
- over-documentation

---

# Context Efficiency Rules

Always minimize unnecessary context usage.

Do NOT read:
- large changelogs
- unrelated category knowledge
- old archived notes

unless required.

Prefer:
- targeted memory retrieval
- category-specific knowledge
- compact summaries

---

# Documentation Update Rules

Before ending major work sessions:

- Update PROJECT_STATE.md
- Update AI_NOTES.md
- Update KNOWN_ISSUES.md if needed
- Add important discoveries only
- Avoid documenting trivial changes

---

# AI Drift Prevention

Always preserve:

- architecture consistency
- UI consistency
- naming consistency
- workflow consistency

Avoid:
- introducing conflicting patterns
- changing architecture unnecessarily
- mixing unrelated coding styles

---

# Research Rules

When internet research reveals:

- important new technology
- major framework changes
- reusable workflows
- valuable debugging discoveries
- future-useful architecture patterns

store them in the appropriate category knowledge files.

Do NOT store:
- trivial findings
- temporary experiments
- redundant information

---

# Knowledge Freshness Rules

When using category knowledge:

- verify note dates
- if knowledge is older than the configured expiration window,
  re-check online sources before relying heavily on the information

After verification:
- update the verification date
- update source links if needed

---

# Memory Architecture Philosophy

Prefer:
- many small focused files

over:
- giant memory documents

Use:
- category separation
- targeted retrieval
- compact summaries
- layered memory loading

Always optimize for:
- low token usage
- efficient retrieval
- high signal-to-noise ratio
