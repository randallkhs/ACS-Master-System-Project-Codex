# Changelog

## Purpose

Track:
- major features
- important fixes
- architecture changes
- significant workflow changes

Avoid logging trivial modifications.

---

# Entry Format

## YYYY-MM-DD

### Added
- new systems
- major features
- integrations

### Changed
- architecture updates
- workflow improvements
- performance optimizations

### Fixed
- important bug fixes
- regression fixes
- stability improvements

### Notes
- important implementation observations
- migration warnings
- future reminders

---

# Logging Philosophy

Prefer:
- compact summaries
- high-value changes
- meaningful milestones

Avoid:
- tiny UI changes
- repetitive implementation details
- excessive session logs

---

# Architecture Changes

Always log:
- major folder restructures
- dependency changes
- threading architecture changes
- database changes
- API workflow changes

---

# Stability Tracking

Document:
- major regressions fixed
- dangerous bugs resolved
- workflow stabilization changes

---

# AI Continuity

The changelog should help future AI agents:
- understand project evolution
- identify major transitions
- avoid repeating previous mistakes

Keep concise and efficient.
